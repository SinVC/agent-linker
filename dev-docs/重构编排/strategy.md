# 重构编排策略

仅供统筹。恢复时读[全局索引](progress.md)与当前步骤进度；静态任务入口为[重构计划](../重构计划/README.md)。

1. 统筹只读必要报告与状态；代码修改、文档整理及具体核查交给代理，避免积累实现上下文。
2. 执行使用新的独立聊天，模型 `gpt-6.1-sol`、推理 `high`。初始交接仅给计划 README 的精确行引用与当前授权步骤的 `steps/NN-progress.md` 路径，让执行会话自行读取步骤及条件文档，不预装实现上下文；验收会话同样按当前步隔离。
3. 串行推进，每轮以最新用户授权为限；当前范围仅记全局索引与当前步骤进度，不写入稳定策略。不得自动推进未授权的后续步骤。
4. 独立验收核实实际差异、验收标准和实跑证据，锁定最终受验版本；执行会话自称完成不能代替验收。FAIL 反馈执行修复并复验；多次失败则新建只读反思聊天再决定修复路径。
5. PASS 且无阻塞后，由 `gpt-6.1-terra` 子代理完成本地提交，默认不 push。核对提交树与最终受验版本一致；构造隔离候选树时必须独立重新验收该候选。
6. 保全已有未提交基线，按增量划定范围，避免混入旧修改。每步从包含前序已交付且已审代码的固定已提交 ref 新建隔离分支/worktree，保留旧交付树；仅导入本轮明确授权并经核验的协调文件。主树协调元数据 HEAD 不可替代代码起点；主树 readonly/backup 等旧修改只保全，不移入候选，不 stash/reset/整文件覆盖。前后核对主树 HEAD/index 与全部 tracked/untracked 哈希及链接元数据快照；成果留在隔离分支/worktree，不强行合回脏主树。将来若回写，再做三方合并和组合验证。每步记录基线、会话 ID、受验版本、证据、阻塞及提交，历史不覆盖。
7. 当前授权步骤文件是执行/验收交接的唯一进度入口。下钻计划维护契约、验收标准和必要代码事实；全局索引只由统筹维护，执行会话不读范围外步骤进度。下钻计划的旧执行记录/勾选 TODO 提示由本隔离规则替代：动态状态与验收证据仅写当前 `steps/NN-progress.md`，README 保留完成复选框，由指定统筹文档维护者在独立验收 PASS、必要验证及本地提交成功确认后更新，执行会话不提前勾选。执行会话不写 README 动态内容，只写当前步骤进度；详细状态仍隔离，也不回写其他步骤。
8. 用户已授权每阶段创建聊天、向相关聊天发消息及参与聊天向统筹报告，无需逐次重复询问；授权不扩展任务阶段。
9. 按用户授权范围创建或恢复自动跟进，状态无变化时安静，仅完成、重要失败或需决策时通知；完成或暂停后停止，暂停/停止条件优先。本轮实例 ID 与状态只记录在全局索引。
